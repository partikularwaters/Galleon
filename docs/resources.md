# Forms and guidance

Galleon owns reusable blanks and examples. Your project owns its adapted agreements
and record locations. Existing project contracts and forms come first: when they
adequately cover the job, the agent should skip Galleon's alternative templates.
Consult a relevant resource only for a gap, a requested illustration, or a useful
starting form. More resources do not mean more required files or approval steps.

## Choose a project arrangement

Charter's guide explains when to use a compact task, linked existing owners,
separated responsibilities, or a real sequential pipeline. Additional examples
address accumulating records and several workflows sharing references. These are
alternatives that may coexist, not a maturity ladder or an exhaustive taxonomy.

For a new small project needing continuity, compact memory is the recommended
starting proposal. For an existing project, prefer its established owners. Split
capture and restore procedures only when different inputs, rules, or maintenance
justify it. The [memory guide](../skills/charter/memory-guide.md) shows concrete layouts
and templates without requiring their application.

Scaffold's [broader arrangement](../skills/scaffold/agency.md) is conditional on
real repeated responsibilities and a selected setup. It is not a day-one default.

## Use a form

For example, adapt the [work agreement](../skills/charter/_templates/work-contract.md)
into the project's existing task record. Name the permitted changes, preserved
behavior, checks, and actual approval boundary. A new file is useful only when it
needs a distinct home. During adaptation, replace library links and skill-only
instructions with the project's own routes and procedures, and remove guidance
intended only for template authors. Name the actual inputs, steps, permitted
changes, checks, and stopping conditions needed to perform the job. Verify links
from the adopted location.
After adoption, future sessions read the project agreement without needing the
original Galleon template. Optional skill use can remain available, but routine
work should not require a skill that the project intends to outlast.

Every installed skill carries its operational resources through local links. This
catalog is for repository browsing; installed skills do not require this page, an
external research session, or another installed skill to perform their own job.
