# Charter

One job: Turn a request into a reviewable plan.

First read the project's entry instructions and relevant records. Find the owner
of this job and inspect the current files; check Git status when Git is available.
Read only what the task needs. Existing project rules and human authorization govern
scope. A skill invocation is not permission to overwrite files or invent approval.

If an important boundary is missing, explain it in plain language, give a small
concrete example, describe the benefit and tradeoff, and offer proportionate choices.
Use existing homes and rules when they suffice. Do not stop repeatedly for decisions
already covered by the current agreement. Resolve unclear authority before consequential
writes. Keep proposed behavior, observed checks, and accepted work distinct.

1. Identify the purpose, existing decisions, inputs, and important unknowns.
2. Name the allowed changes, preserved work, checks, and completion conditions. Scale detail to risk; hashes and separate approval files are optional unless the project requires them.
3. When structure is needed, use [shape guidance](guide.md) and adapt a small template. Explain where it belongs and why. A template does not authorize its application.
4. Present the plan and any consequential choices. Follow the project’s approval rules; do not implement the plan during Charter.

Boundaries: Implementation, applying a structural mapping, accepting results, or launching other sessions.

## Project inputs and conditional resources

Always resolve the project's instructions, selected task, planning owner, actual
inputs, and relevant settled decisions. Use its existing contracts and planning
form first. When they adequately cover the job, do not load Galleon's alternative
templates or propose another structure. Keep the method's scope and checks.

| When | Read | Use it to |
| --- | --- | --- |
| A consequential working boundary or structural owner is missing | [Shape guidance](guide.md), relevant section only | Select the smallest justified agreement and one useful alternative. |
| Session work needs a durable route, and existing rules do not supply it | [Memory guidance](memory-guide.md), relevant form or split section | Compare compact, linked, and separated forms and show the recommended procedure. |
| The scope of an edit cannot be understood through existing records | [Change-impact guidance](change-impact.md) | Identify real consumers, failure patterns, and evidence limits before planning writes. |
| File reading cost is a relevant migration factor, and no project command suffices | [Optional estimator](token-count.md) | Measure explicit files without inferring a split or model-exact count. |
| A local plan form is missing or explicitly requested | [Plan form](_templates/plan.md) | Adapt a useful blank into the project's selected home or a chat draft. |

Do not read every example, all reference topics, or unrelated UI rules by default.
Read one relevant example when a concrete illustration helps the human choose.
The guides name the local examples and templates. Source citations are optional
background, not instructions to research ICM or install another skill.
