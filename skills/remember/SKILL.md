# Remember

One job: Leave a useful, verified starting point for continuation.

First read the project's entry instructions and relevant records. Find the owner
of this job and inspect the current files; check Git status when Git is available.
Read only what the task needs. Existing project rules and human authorization govern
scope. A skill invocation is not permission to overwrite files or invent approval.

If an important boundary is missing, explain it in plain language, give a small
concrete example, describe the benefit and tradeoff, and offer proportionate choices.
Use existing homes and rules when they suffice. Do not stop repeatedly for decisions
already covered by the current agreement. Resolve unclear authority before consequential
writes. Keep proposed behavior, observed checks, and accepted work distinct.

1. Find the project’s capture procedure and existing owners for decisions, progress, evidence, and next action. Do not require a memory folder if an existing record already owns this job.
2. Check actual files and result records before relying on conversation recall. Record only verified state, material limits, and actual decisions; do not save secrets or unnecessary personal details.
3. Update the agreed record homes, linking rather than duplicating facts. Preserve earlier decisions and unrelated work.
4. Verify the saved state and return the next action. Capture is not proof that a fresh session can resume; recommend a proportionate observation when that claim matters.

Boundaries: Creating a new memory architecture, restoring the project, inventing approval, or independently closing work.
