# Save work with a clear route back

Be opinionated about preserving useful session work, not about imposing a folder
skeleton. Prefer a verified state record and an explicit save/resume procedure when
work needs to continue beyond this conversation. Use the project's existing style
when it supplies those responsibilities.

## Reading this guide

An adequate existing capture procedure takes precedence. If one is missing, read
the alternatives section and propose a proportionate choice. If concerns emerged
during an established capture, read the modes/splitting section instead. Neither
case authorizes creating or reorganizing memory during Remember.

## Offer concrete alternatives when a boundary is missing

- Compact: memory/CONTEXT.md holds capture and restore modes; memory/state.md holds
  the verified job, decisions, limits, and next action. Few files, but state needs
  maintenance as work grows.
- Linked homes: memory/CONTEXT.md routes to existing progress, decision, and task
  owners. Avoids duplication, but depends on accurate routes.
- Separated: progress, session continuity, and decisions have distinct owners.
  Useful for different readers, but costs more navigation and maintenance.

For example: "Your task file owns the result, but there is no agreed place for the
next session's starting point. We could use its current-state section, or propose
memory/CONTEXT.md and memory/state.md. Either would preserve the next action without
copying the result. Which fits your project?"

Charter owns the fuller shape examples and templates when installed. If unavailable,
explain the concrete alternatives in chat and request the needed planning step;
do not depend on another installed skill to perform capture at existing homes.

## Keep the two modes explicit

Capture writes verified state at agreed owners. Restore reads, checks current work,
and reports the next action without silently rewriting records. Remember performs
capture only. A plain resume request can use the project's restore procedure;
there is no requirement to turn restoration into another skill.

Recommend splitting memory/CONTEXT.md into a router plus capture.md and restore.md
only when their inputs, rules, or maintenance need it. A separated state layout does
not automatically require separate procedure files. Existing restoration.md or other
coherent names can remain.

If the capture boundary is missing, propose it through Charter; do not create it
while saving. If boundaries already cover capture, continue without repeating old
approval questions. Do not add routine snapshot manifests or planted-drift tests
unless the project's risk, promised behavior, or existing rules justify them.

Save the facts that support continuation, not an entire conversation. Keep private
paths, secrets, and unnecessary approval narratives out of public-facing records.

## Save an optional reading-cost summary

If the project has adopted a reading-cost routine, follow its declared files,
checkpoints, command, and summary owner. The purpose is to notice growing routine
context, keep agents focused, and support progressive reading. A count makes cost
visible; it cannot guarantee clear files or good navigation.

A useful reading set includes the actual entry/router, current continuation record,
active plan or phase contract, and references that phase needs. Source files belong
in it only when relevant. Exclude dependencies, generated files, old history, and
prior count reports by default. Use existing project owners, not a new memory layout.
Resolve the set into explicit file arguments rather than scanning the repository.

During authorized capture, save the measured paths, measurement point, approximate
method, result, limits, and useful interpretation. State whether it concerns the
completed phase or the next phase. Link to a fuller report only when useful and
agreed. Report failed measurements as failures. Avoid repeatedly updating a record
because saving the summary changes its own length.

At resume, the project's read-only procedure can read that summary and remeasure
if required. Remember does not perform restoration or set up automatic hooks.
Saved counts are not current measurements, and equal counts do not prove equal
contents. Compare trends only across comparable sets and methods. If ordinary
results need no action, continue; do not ask for a decision after each count.
Recommend selective reads or a structural review only when real needs justify
one, following project approval rules. Do not restructure during capture.

## When already separated procedures become crowded

Distinguish accumulated evidence, unnecessary repetition, and genuinely different
jobs. Evidence keeps its existing owner, while a cohesive procedure can use clearer
headings and selective reads. If recurring jobs need different inputs, owners, or
checks, recommend a Charter proposal for a short mode entry routing to focused
procedures. Keep mandatory common rules at one owner, and let each selected case
narrow them. Restore and its cases remain read-only. More small files do not
necessarily reduce the whole reading cost. Remember reports the concern; it does
not migrate procedures or create competing copies while capturing.

## Current records and numbered history

If the project's existing capture procedure authorizes rollover, move coherent
settled threads or completed milestones to its numbered history collection, update
its index, and retain open work and the next action in current memory. This is an
agreed record-maintenance operation, not permission to redesign memory. Resolve a
missing structural agreement through planning before creating new owners.

Use stable archive-order numbers and descriptive topics; separate collections have
independent sequences. Check preservation before removing moved detail. Keep task
status, decisions, and evidence authoritative at their existing owners. Moving a
thread into history does not complete its outstanding work. An index.md lives
inside the collection it lists; the parent entry links there without duplicating
the listing. A CONTEXT.md needs a real contract or entry responsibility beyond a
contents list. Restore remains read-only and loads selected history only as needed.
