# Scaffold

One job: Establish only the agreed missing structure.

First read the project's entry instructions and relevant records. Find the owner
of this job and inspect the current files; check Git status when Git is available.
Read only what the task needs. Existing project rules and human authorization govern
scope. A skill invocation is not permission to overwrite files or invent approval.

If an important boundary is missing, explain it in plain language, give a small
concrete example, describe the benefit and tradeoff, and offer proportionate choices.
Use existing homes and rules when they suffice. Do not stop repeatedly for decisions
already covered by the current agreement. Resolve unclear authority before consequential
writes. Keep proposed behavior, observed checks, and accepted work distinct.

1. Identify the exact target, agreed creation list, contents, and checks. If they are unclear, return a small proposal rather than designing while writing.
2. Inspect every destination and parent, including files, directories, symlinks, and case-insensitive collisions. Stop before writing if any target already exists.
3. Create only the agreed files. Do not initialize Git or install dependencies unless authorized. For consequential multi-file changes, agree on preservation and recovery first.
4. Check content, links, and owners. Report actual creations and any partial failure. Successful setup does not establish successful first use or restoration.

Boundaries: Overwriting, reorganizing existing content, executing the first job, or claiming readiness without observation.

## Project inputs and conditional resources

Always resolve the exact target, agreed setup, creation list and contents, existing paths, preservation requirements, and checks.
Use the project's existing contract and forms first. If they adequately cover the
job, skip Galleon's alternative templates and work within those boundaries.
